## dev_docs.md

AI 주도 개발을 하다보면 이해하는 비용이 개발하는 비용보다 커질 때가 있음. 

그렇게 되면 프로젝트가 발전할 수 없음. 

이 문서는 ai가 구현한 구체성을 이해하고 설명하기 위한 문서가 아님. 

전체적인 구조를 이해할 수 있도록 사람에 의해 높은 가독성으로 관리되어야 하는 고급 자원임. 

**AI가 짠 코드는 현실적으로 이해하고 수정하기 어려움. 프로젝트 마지막에 가서는막 쓰겠지만 초반부터 핵심 로직을 AI로 짜면 수정이 어려움. 따라서 손으로 이해하며 짜는 핵심 코드 구조를 여기에 설명함**

## 에이전트 구조

우선 모든 쿼리는 main.agent.query() 로 받을 거임. 

그리고 이 함수는 main에서 정의된 에이전트 루프를 타고 최종 결과를 답변함. 

이 최종 입출력 형식은 대회 주최측에서 제한하는 json 방식을 따라야함. (지금은 아님)

서버는 마지막에 구성해서 이 main.py를 import 하는 방식으로 api를 구성하면 됨. 

나중에 바꿔도 무방하지만, main 안에서 여러 에이전트를 정의하고 자기 호출로 query를 마무리하면 좋겠음.

main에서는 적절하게 에이전트를 호출함. 에이전트는 /agents 에 정의됨. 

**main에서 절대 도구를 호출하면 안됨. agint의 결과에 따라 어떤 agint를 선택할지 분기하는 것이 main 의 역할임**

## Agent
모든 agent는 Agent 객체를 상속함. 기본적으로 query는 "단발성" 임. 세션과 도구 호출 기록이 없는 입력임. agent에서 알아서 도구 호출을 해서, 목표하는 결과를 뽑아내야함. 
이 정의는 개발하면서 유연하게 바꿀 수 있음. 정의를 바꾸는 건 되지만, 예외를 만들지는 말것. 

### A1 query_parser
쿼리를 이해하고 분석하는 것이 목표임. json 결과를 바탕으로 분석함. 
이 단계에서 직접 온톨로지 쿼리를 사용하여 질의에서 모순이 있는 문제를 걸러내면 좋겠음. 

## Tool
도구는 에이전트가 사용하는 말 그대로 "도구"임. 

지금 구현된 도구로는 "벡터 db를 조회하는 도구" 가 있음. 

"각 에이전트가 사용하는 도구를 제한" 하면 좋겠음. 현재는 toolmanager에 tool 등록해서 쓰는 구조인데, 에이전트마다 tool 제한이 있으면 좋을듯. 

### T1 meta column table
사용자 질의에 가장 관련있는 테이블 컬럼명을 추출해옴. 
table filter를 설정할 수 있기 때문에 A1에서 추출한 카테고리를 이용하면 될듯.
